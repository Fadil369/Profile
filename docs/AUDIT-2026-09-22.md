# elfadil.com audit and release — 22 September 2026

## Scope and inventory

Updated the existing React/Vite profile and optional Three.js workspace in this checkout. Preserved changes already present when the audit began. No new Worker, database, form delivery service, or parallel profile was created.

Cloudflare API inventory found 219 Workers, including `profile`, `elfadil-pages-proxy`, and `elfadil-work-router`. The active apex route belonged to `profile`; the older local `workers/elfadil-landing` configuration was not the deployed owner. `www.elfadil.com` had proxied DNS but no Worker route. The Mac inventory connection timed out; local source, ecosystem manifest, and live Cloudflare routes established the target. No unrelated commerce, clinical, or ERP state was changed.

Deployed production version: `e4dc0cf0-eec8-4eb4-bcac-a3d2a60a3275` (existing Worker `profile`, apex and www routes).

Previous production version: `27cc405d-9a84-4f26-af45-3060f96e06fe`.

## Remaining limits

- Email opens the visitor's mail application. Mail delivery was not exercised, and no message was sent. A replacement booking schedule is needed to restore actual calendar booking.
- Existing biographical dates, expertise labels, and remaining narrative claims are owner-provided; this technical audit does not independently verify credentials or outcomes.
- LinkedIn rejects automated HTTP probes (999). Its profile link remains available; this response does not establish that the human-facing page is broken.
- The optional Three.js workspace is a separate ~160 KB gzip chunk. Vite flags its uncompressed size; it is not downloaded as the initial homepage bundle.
- Ecosystem dots mean best-effort HTTP reachability, not successful product operation; redirects or blocked probes remain unconfirmed.
- Legacy downloaded source assets remain in the working tree but are excluded from the deployment build. The Echo Danah build output is a distinct informational page.
- Changes have not been committed or pushed; the checkout contained pre-existing uncommitted work.

## Reproduce

```bash
npm --prefix landing ci
npm --prefix landing run build
npx --yes wrangler@4.135.0 dev --ip 127.0.0.1 --port 8794 --inspector-port 9238 --local
# In another terminal:
npm --prefix landing test
# Same suite against production:
PROFILE_BASE_URL=https://elfadil.com npm --prefix landing test
```

To roll back Worker code and assets, with Cloudflare credentials available:

```bash
npx --yes wrangler@4.135.0 versions deploy 27cc405d-9a84-4f26-af45-3060f96e06fe@100% --yes
```

Version rollback does not revert route configuration. The added `www` route continues to use `profile`; removing it would restore the previous unhandled hostname.
